Context Windows in Practice

The context window is a physical budget, and three things quietly spend it: verbose tool results, long conversations, and exploration. This lesson is the four defences — trim, extract, position, persist — and when to reach for each.

Domain 5 Context Management & Reliability · 15% Covers TS 5.1, TS 5.4 Time ~15 min

1. Two failure modes, one budget

Every TS 5.1/5.4 stem describes one of two degradations:

  • Loss by compression. A long support conversation gets progressively summarised, and the summary keeps the gist but flattens the specifics — amounts become "a refund", dates become "recently", the customer's stated expectation disappears. Later turns then act on the vague version. TS 5.1
  • Loss by dilution. Nothing is deleted, but so much has accumulated — 40-field order objects, hundreds of grep hits — that the model starts answering from "typical patterns" instead of the specific classes it read an hour ago. The facts are technically in context and functionally invisible. TS 5.4

2. Lost in the middle

The best-documented shape of dilution: models reliably process what sits at the beginning and end of a long input, and under-attend to the middle.

the "lost in the middle" effect — position is a reliability variable, so use it deliberately

The prescribed counter-moves when aggregating many inputs (e.g. subagent findings into a synthesis prompt) TS 5.1:

  • Put a summary of key findings at the beginning of the aggregated input — the high-reliability slot carries the load-bearing facts.
  • Organise the detailed body with explicit section headers, so retrieval has landmarks instead of a undifferentiated middle.

3. Trim at the source, extract what must survive

Tool results are the biggest silent spender: one lookup_order returns 40+ fields when the case needs five. Multiply by every lookup in a session and the window fills with warehouse codes TS 5.1.

trim what enters · extract what must never be summarised away

The two named mechanisms, and how they differ:

  • Trimming keeps irrelevant tokens out: cut verbose tool output to the relevant fields before it accumulates.
  • The case-facts block keeps critical tokens alive: transactional facts — amounts, dates, order numbers, statuses, the customer's stated expectation — are extracted into a persistent structured block included with each prompt, outside whatever summarisation the rest of the history undergoes. Compression can now flatten the conversation without flattening the numbers. Multi-issue sessions get the same treatment per issue.

The multi-agent variant TS 5.1: when a downstream agent has a limited context budget, modify the upstream agent to return structured data — key facts, citations, relevance scores — instead of verbose prose and reasoning chains. Same trim-at-source instinct, applied at an agent boundary; it's also what makes L14's provenance mappings affordable.

4. Long exploration: persist outside the window

TS 5.4 is the codebase-exploration version. Symptoms of an exhausted exploration session: inconsistent answers, and references to "typical patterns" where an hour ago it cited the actual class names. The defences escalate:

DefenceMechanismReach for it
Subagent delegation Verbose investigation runs in an isolated context (L02/L09's Explore); main agent keeps coordination-level understanding only Before exploration starts — the preventive move
Scratchpad files The agent writes key findings to a file as it works, and re-reads them for later questions — memory on disk instead of in-window Long sessions where findings must outlive context churn
Summarise-then-spawn Close each phase by summarising its findings; inject the summary into the next phase's subagents as initial context Multi-phase work — each phase starts clean but informed
/compact Claude Code compresses the conversation in place Mid-session, when discovery output has filled the window
Crash-recovery manifests Each agent exports structured state to a known location; on resume, the coordinator loads the manifest and injects it into agent prompts Long multi-agent runs that must survive interruption

no re-exploration after a crash — the state lived outside every context window

Notice the family resemblance to L04: a resumed session restores stale conversation; a loaded manifest restores curated, structured state. The exam prefers state you designed over history you replayed.

One sentence for the whole lesson

Decide what must survive, and give it a home the budget can't touch — a facts block outside the summary, a scratchpad outside the window, a manifest outside the process. What merely passed through gets trimmed on the way in and positioned deliberately when it matters.
